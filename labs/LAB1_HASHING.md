# Lab 1: Хеширование

SHA-256 берёт любые данные и превращает в 32 байта. Одинаковый вход — одинаковый выход, всегда. Но стоит поменять один бит — и результат неузнаваемо другой. Это называют лавинным эффектом, и на нём стоит вся криптография в блокчейне: целостность блоков, адреса кошельков, Proof of Work.

Обратить хеш нельзя. Нельзя по хешу восстановить данные. Нельзя подобрать другие данные с тем же хешем (ну, за разумное время). Единственный способ найти хеш с нужным свойством — перебирать входы. Собственно, это и есть майнинг.

## Задание

Файл: `labs/lab1/crypto.rs`

Три функции:

1. `sha256(data) -> [u8; 32]` — обёртка над крейтом `sha2`. Создаёшь хешер, скармливаешь ему данные, забираешь результат. Три строки кода.

2. `meets_difficulty(hash, difficulty) -> bool` — тут интереснее. `difficulty` — это количество нулевых **бит** в начале хеша. Не байтов, а именно бит. `difficulty=8` значит первый байт = 0. `difficulty=12` значит первый байт = 0 и старшие 4 бита второго байта тоже нули. Придётся повозиться с битовой маской: `0xFF << (8 - остаток)`.

3. `pubkey_to_address(pk) -> String` — адрес это `hex::encode(sha256(pk.as_bytes()))`. Одна строка по сути, но теперь ты понимаешь откуда берутся адреса в блокчейне — из публичного ключа через хеш.

## Демо

```bash
cargo run --bin lab1_demo
```

Две вещи. Лавинный эффект: "hello" и "Hello" дают совершенно разные хеши, 32 из 32 байтов отличаются. И цена сложности: при `difficulty=8` майнинг находит nonce за ~100 попыток, при `difficulty=20` — за миллион с лишним. Каждые +4 бита сложности это примерно ×16 к работе. Запомни эту экспоненту — она объясняет почему Bitcoin тратит столько электричества.
