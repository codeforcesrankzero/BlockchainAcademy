# Lab 3: Блоки и Proof of Work

Транзакции сами по себе — просто отдельные заявления. Блок собирает их в пачку и скрепляет единым хешем. Каждый блок ссылается на предыдущий через `prev_hash` — так получается цепочка, которую нельзя незаметно изменить: поменяешь один блок — сломается хеш, а значит и все последующие блоки.

Но кто решает какой блок следующий? Proof of Work: чтобы предложить блок, нужно подобрать `nonce` — число, при котором хеш заголовка начинается с определённого количества нулей. Это та самая `meets_difficulty` из lab1. Работа дорогая (перебор), а проверка дешёвая (один хеш). Поэтому сеть может быстро убедиться что ты честно потратил ресурсы.

## Задание

Файл: `labs/lab3/block.rs`

`txs_root` — сводит все транзакции блока в один хеш. Идея: берёшь первый `tx.hash()`, это текущий root. Для каждого следующего: `root = sha256(root || tx.hash())` — конкатенация и ещё один хеш. Нет транзакций — `[0u8; 32]`. Это упрощённый аналог Merkle root из настоящих блокчейнов.

`header_hash` — хеш всего заголовка блока. Собери структуру `Header { height, timestamp, prev_hash, nonce, difficulty, txs_root }`, сериализуй через `bincode`, отдай в `sha256`. Именно этот хеш и должен удовлетворять сложности.

`mine` — крутишь `nonce` от 0 пока `meets_difficulty(&self.header_hash(), self.difficulty)` не вернёт `true`. Возвращаешь блок с найденным nonce. Может показаться что цикл бесконечный — нет, при нашей сложности он находит ответ быстро.

Типичная ошибка — перепутать условие выхода из цикла. Если блок «замайнился» мгновенно и тест на сложность красный — проверь, не возвращаешь ли ты первый попавшийся nonce вместо правильного.
