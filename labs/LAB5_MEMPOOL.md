# Lab 5: Мемпул

Когда пользователь отправляет транзакцию — она не попадает в блок мгновенно. Она ждёт в мемпуле (memory pool). Майнер собирает следующий блок — лезет в мемпул, выбирает транзакции, включает их в блок. После майнинга — убирает включённые транзакции из мемпула.

Зачем вообще фильтровать на входе? Представь: майнер берёт из мемпула транзакцию с невалидной подписью, включает в блок, тратит CPU на майнинг — а сеть блок отклоняет. Зря работал. Поэтому мемпул проверяет транзакции заранее.

## Задание

Файл: `labs/lab5/mempool.rs`

`add_tx(tx, state)` — добавить транзакцию в мемпул, но только если она валидна:
- Подпись проходит `tx.verify()`
- Nonce совпадает с текущим в state (`state.nonce_of(&tx.from) == tx.nonce`)
- Баланс достаточен (`state.balance_of(&tx.from) >= tx.amount`)
- Такой транзакции ещё нет в мемпуле (проверяй по хешу)

Каждая проверка — свой вариант `MempoolError`. Не мешай их в одну ошибку.

`select_txs(state, max_count)` — выбрать до `max_count` транзакций для блока. Coinbase не добавляй — её создаёт `mine_block`. Возвращай транзакции отсортированными по nonce: если Алиса отправила две транзакции (nonce 0 и nonce 1), они должны идти именно в таком порядке, иначе `apply_block` упадёт на второй.

`remove_txs(hashes)` — удалить из мемпула транзакции по их хешам. Вызывается после того как блок замайнен.

`len` — сколько транзакций в мемпуле.
