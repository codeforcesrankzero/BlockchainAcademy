# Lab 4: Состояние и цепочка

До сих пор мы работали с отдельными блоками. Но блокчейн — это не просто список блоков, а ещё и состояние: кто сколько владеет прямо сейчас. Без состояния невозможно проверить транзакцию — откуда ты знаешь что у Алисы хватает монет?

Состояние (`State`) — это два словаря. `balances` хранит баланс каждого адреса. `nonces` хранит сколько транзакций адрес уже отправил. Nonce нужен против replay-атак: без него можно было бы взять чужую подписанную транзакцию и отправить её повторно.

`Chain` — это собственно блокчейн. Хранит блоки, знает текущее состояние, умеет валидировать и добавлять новые блоки.

## Задание

### `labs/lab4/state.rs`

`balance_of` и `nonce_of` — геттеры. Адреса нет в словаре — возвращай 0.

`apply_tx` — самая содержательная функция. Два случая:

Coinbase (награда майнеру, `tx.is_coinbase()`): просто добавь `amount` к балансу `to`. Без проверок — coinbase гарантирована протоколом.

Обычная транзакция: проверь подпись (`tx.verify()`), потом nonce (должен совпадать с `nonce_of(from)`), потом баланс (>= amount). Всё ок — спиши у `from`, начисли `to`, увеличь nonce на 1. Что-то не так — верни ошибку, состояние не должно измениться.

`apply_block` — пройди по всем транзакциям блока и вызови `apply_tx`. Если хоть одна упала — блок невалиден.

### `labs/lab4/chain.rs`

`genesis` — генезис-блок. height=0, prev_hash из нулей, без транзакций, замайненный. С него начинается любая цепочка.

`tip_hash` и `height` — хеш и высота последнего блока в цепи.

`add_block` — валидация нового блока. Проверок много, порядок важен:
1. Высота ровно на 1 больше текущей
2. `prev_hash` совпадает с хешем текущего последнего блока
3. Timestamp не меньше чем у предыдущего
4. Хеш заголовка проходит `meets_difficulty`
5. Первая транзакция — coinbase с правильной наградой (50 монет)
6. Остальные транзакции — не coinbase
7. `apply_block` не упал на этих транзакциях

Любая проверка провалилась — блок отклоняется. Это и есть консенсус: все ноды проверяют одни и те же правила.

`mine_block` — собери блок из coinbase + переданных транзакций, правильно заполни заголовок и замайни.

## Тесты

```bash
cargo test --test lab4_tests
```

Тесты проверяют и happy path и ошибки: двойное списание, неправильный nonce, невалидная подпись. Если у тебя `apply_tx` не возвращает ошибку где надо — тест это поймает.
